# A picture at every step

All 803 instructional steps across 97 classes now have an individual **illustrated step map** rendered directly in the walkthrough. This includes the 72 AlmaLinux steps and the Linux workplace/troubleshooting variants. No class-level accordion is required to see the step picture. The existing illustrated screen reference for each class also appears directly at each step, so students can see the software context while following the individual map. Related steps share that screen reference; it is explicitly labeled as a class reference rather than an exact capture of the action.

These are authored-data diagrams, not newly captured product screenshots. Each picture identifies the work context, numbers the first small actions, shows command examples when present, and names the expected observation without claiming it happened. Long instructions and complete command blocks remain selectable below the image. Existing vendor screenshots remain separately identified and available. Product screenshots and step maps are not interchangeable evidence of execution.

The SVG maps are generated by `tools/generate-step-pictures.mjs` from the audited instruction data. They contain no scripts, links, external images, or interactive controls. The generator escapes text and records instruction/file hashes in `content/screenshots/step-pictures.json`. All pictures carry an illustration watermark. It does not invent a software layout, a clicked control, or successful command output.

Refresh after curriculum edits:

1. `npm run screenshots:coverage`
2. `npm run pictures:generate`
3. `npm run pictures:check`

The visual coverage check requires a unique matching asset for every real step and rejects stale hashes. The independent `screenshots:check` still measures authentic reviewed captures; diagrams do not make that check pass.

The shared reader now breaks prose into smaller numbered actions without rewriting paths, addresses, conditions or commands. A glossary explains common terms. Mobile uses a step selector rather than a long navigation list; next/previous remain available. Pictures enlarge into a scrollable canvas so text can be read on a phone. Detailed evidence notes are collapsed, while the expected result remains visible. Checkboxes keep the existing independent per-step note storage and do not certify a completed lab.
