# Sourced screenshot matching

The user confirmed there is no connected training lab and authorized pooling screenshots from multiple sources using judgment. The acceptance scope is an actual-interface reference at every instructional step, with truthful provenance and clearly identified source-example differences. It is not exact lab-execution capture coverage.

Selection rules:

- Azure UI actions use Azure Portal screenshots; a PowerShell command or SSH session uses its actual terminal interface.
- AlmaLinux installer actions use Anaconda. Day-to-day desktop actions use AlmaLinux 9 GNOME40 or the matching upstream GNOME application/version. Windows-host setup steps use Windows/VMware interfaces.
- SSMS, SQL Setup, Configuration Manager, DNS/GPO tools and Failover Cluster Manager are distinct interfaces.
- Planning/interview/evidence actions may show the appropriate notes editor or file manager, since they have no product wizard or live infrastructure result to capture.
- A source UI reference may be reused for related actions in the same interface. Its exact role is recorded per step. Orientation references identify where to work; they do not claim to show a specific command or completed action.
- Original labels, commands and results in third-party screenshots are not rewritten. Course values remain in the selectable instructions. Version, theme, username, addresses, OS-image and hardware-model differences are called out.
- Diagrams, AI illustrations, unrelated class images, broken URLs and invented output do not count as screenshots.

All source images are served locally with their source URL, credit, license/permissions link, SHA-256 and step association. The generation/check tool rejects stale instruction associations, changed source files and missing assets. The independent exact-target-capture inventory remains separate.
